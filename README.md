# ByeDPI × TG Desktop

Маленький GUI на PySide6 для Linux (делался под Void), который управляет двумя локальными прокси:

| Что | Движок | Адрес | Куда прописать |
|---|---|---|---|
| YouTube, Discord и другие сайты | [byedpi](https://github.com/hufrea/byedpi) | SOCKS5 `127.0.0.1:1080` | в браузер и клиент Discord (кнопками) |
| Telegram | [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) | MTProto `127.0.0.1:1443` | в Telegram Desktop (кнопкой) |

Приложение само ничего не проксирует, оно только запускает и останавливает эти процессы, показывает их логи и состояние.

## Установка

```sh
./install.sh
byedpi-tg
```

Что делает `install.sh`:
1. ставит через xbps `git gcc make python3 curl xdg-utils`;
2. клонирует и собирает byedpi в `~/.local/share/byedpi-tg/byedpi`;
3. клонирует tg-ws-proxy рядом;
4. создаёт venv и ставит `PySide6-Essentials`, `httpx[http2]`, `certifi`, `cryptography`, `curl_cffi`;
5. кладёт команды `~/.local/bin/byedpi-tg` и `byedpi-tg-diag`, а также ярлык в меню приложений.

Повторный запуск `./install.sh` обновляет оба движка. Удаление: `./install.sh uninstall`.

> На **musl**-варианте Void колёса PySide6 из pip не встанут. Установщик это заметит и остановится.

## Как пользоваться

**Перед началом выключи VPN.** Если трафик идёт через туннель (включая kill switch), все проверки показывают работу VPN, а не обхода DPI. Приложение предупредит об этом жёлтой плашкой.

**YouTube и Discord**
1. Нажми «Проверить DNS» (см. раздел ниже). Если DNS врёт, подбор стратегий бесполезен.
2. На вкладке «Подбор стратегий» нажми «Подобрать стратегию». Лучший результат применится сам, а топ-8 попадут в выпадающий список «Стратегия».
3. Нажми «Запустить» и подключи приложения:
   - **«Браузер»** откроет браузер в отдельном профиле с готовыми настройками. Основной профиль не меняется, и его можно не закрывать. Расширения и пароли там свои.
   - **«PAC для своего браузера»** нужен, чтобы остаться в обычном профиле. Создаётся файл автонастройки, адрес попадает в буфер, его надо вставить в Firefox: Настройки → Параметры сети → «URL автоматической настройки прокси». Через byedpi идут только YouTube и Discord, а при выключенном прокси браузер работает напрямую.
   - **«Discord»** запустит клиент с `--proxy-server` (системные настройки прокси он не читает). Перед этим закрой Discord полностью, включая трей. Если клиента нет, сайт откроется в браузере.
4. Если что-то не грузится, нажми «Проверить сервисы»: покажет каждый адрес и причину сбоя.

**Голос Discord.** Голос и демонстрация экрана идут по UDP мимо SOCKS, поэтому byedpi на них не влияет. Для них есть отдельный режим на `nfqws`, см. [раздел ниже](#голос-discord-через-nfqws).

**Telegram**
1. Включи переключатель.
2. Нажми «Применить в Telegram»: откроется `tg://proxy?...`, Telegram предложит подключиться.
3. Если не открылось, жми «Копировать ссылку», отправь её себе в «Избранное» и нажми на неё.

Secret генерируется один раз и сохраняется, поэтому в Telegram прокси добавляется один раз.

**Не грузятся фото и видео в TG?** Впиши в «Доп. флаги» `--dc-ip 4:149.154.167.220`. Это совет из README tg-ws-proxy.

## Подбор стратегий: как это устроено

- **Список.** Стратегии из Android-приложения [ByeByeDPI](https://github.com/romanvht/ByeByeDPI) плюс кандидаты с разбиением TLS-записи для Cloudflare, где живёт Discord. Кнопка «Обновить список» скачивает свежий список ByeByeDPI в `~/.config/byedpi-tg/strategies.list`.
- **`{sni}`** в стратегиях — поддельное имя сайта в фейковом ClientHello (флаг `-n`). Задаётся полем «Fake SNI».
- **Что проверяется.** 6 адресов YouTube, включая домен видео и реальный ближайший видеосервер, и 6 адресов Discord: сайт, API, gateway, CDN, медиа, скачивание. Свои адреса можно добавить в `custom_targets` в конфиге.
- **Как засчитывается адрес.** С отпечатком Firefox (`curl_cffi`), потому что ClientHello от curl устроен иначе и стратегия может работать только для него. Там, где важен объём, ответ должен быть больше 64 КБ и скачаться целиком: ТСПУ часто пропускает рукопожатие и замораживает поток после ~16 КБ.
- **Подстройка TTL.** Если сервис прошёл не полностью, для лучших стратегий с фейками перебираются другие TTL: нужное значение зависит от того, на каком хопе стоит DPI.
- **Раздельные правила.** Если лучшие стратегии для YouTube и Discord разные, они объединяются через группы byedpi (`-H` и `-An`), и итог проверяется ещё раз. Остальные сайты получают лучшую общую стратегию.

То же можно сделать из консоли, отчёт сохранится в `~/.config/byedpi-tg/diagnostic.txt`:

```sh
byedpi-tg-diag                 # только диагностика, около минуты
byedpi-tg-diag --pick --apply  # подбор и сохранение лучшей стратегии, до ~15 минут
```

Приложение также добавляет к стратегиям два флага: `-X` (только IPv4, отключается через `"ipv4_only": false`) и таймаут `-T`, если в стратегии есть триггер `-At`. Без таймаута этот триггер срабатывает только на RST, а ТСПУ чаще молча дропает пакеты.

Стратегии «протухают»: провайдеры обновляют фильтры волнами. Если сервис отвалился, попробуй следующие из выпадающего списка, потом заново запусти подбор, потом обнови список.

Заморозка на Cloudflare может зависеть от IP, а не от SNI. Тогда стратегии могут не помочь совсем: в отчёте будет «заморозка» у адресов Discord при любых аргументах.

## Голос Discord через nfqws

Режим перед началом голосового UDP-потока посылает поддельные пакеты, чтобы сбить DPI с толку. Ему нужны root и правила iptables, поэтому он ставится отдельно:

```sh
./install.sh voice
```

Затем нажми «Запустить» в карточке «Голос Discord» и введи пароль sudo: он передаётся только в `sudo` и нигде не сохраняется. Из консоли: `byedpi-tg-diag --voice start|stop|status`, профиль задаётся через `--voice-profile`.

Проверить голос автоматически нельзя, для этого нужна сессия Discord. Зайди в голосовой канал: если он зависает на «Подключение к RTC», выбери следующий профиль.

| Профиль | Что делает |
|---|---|
| `quic6` | перед пакетами Discord и STUN шлёт фейковый QUIC Initial 6 раз |
| `quic11` | то же 11 раз |
| `stun3` | фейки STUN и QUIC, 3 раза |
| `wide` | фейки для любого UDP на голосовых портах, в том числе нераспознанного |

Что меняется в системе:
- в `/usr/local` появляются `sbin/byedpi-tg-voice` и `lib/byedpi-tg/`, принадлежащие root. `nfqws` собирается из закреплённой версии zapret (`v72.13`, коммит проверяется);
- в `iptables -t mangle` добавляется цепочка `BYEDPI_VOICE`. Она ловит только исходящий UDP на портах `19294-19344` и `50000-50100` и только первые 12 пакетов каждого потока;
- `nfqws` сбрасывает root сразу после запуска.

Что важно знать:
- Правила действуют только на физическом выходе. При включённом VPN голос идёт через туннель, и режим на него не влияет. Адреса с отдельным маршрутом через этот выход, например сервер VPN, исключены.
- Если `nfqws` упадёт, пакеты пойдут дальше благодаря `--queue-bypass`, а сеть не сломается.
- Автозапуска нет. Режим работает до нажатия «Остановить» или до перезагрузки и не останавливается при закрытии приложения.
- Только IPv4 и только `iptables`. Если у провайдера заблокированы сами IP-адреса голосовых серверов, фейки не помогут.

**Статус проверки.** Хелпер и правила iptables проверены под root в виртуальной машине, но с заглушкой вместо `nfqws`. Работа с настоящим `nfqws`, реальным ТСПУ и клиентом Discord пока не проверена.

Удаление: `./install.sh uninstall`.

## Тесты

```sh
python -m unittest discover -s tests -v
tests/vm/run.sh                       # хелпер голоса под root в одноразовой ВМ (нужен qemu)
NFQWS=путь/к/nfqws tests/vm/run.sh    # то же с настоящим nfqws
```

Настоящий `ciadpi` работает против симулятора DPI на loopback. Тесты проверяют логику подбора и групп, но не заменяют проверку в реальной сети.

## Если виноват DNS

byedpi получает от браузера имя сайта и сам спрашивает его адрес у **системного** DNS. Если провайдер подменяет ответы для YouTube или не отдаёт их вовсе, не поможет ни одна стратегия. При этом все стратегии падают разом, на всех устройствах в этой сети.

Кнопка «Проверить DNS» спрашивает адреса YouTube и Discord у системы и, для сравнения, через DNS-over-HTTPS. Затем проверяет, что системные адреса лежат в сетях Google и Cloudflare.

Если DNS подменён, на Void ставим локальный шифрованный DNS:

```sh
sudo xbps-install dnscrypt-proxy
sudo ln -s /etc/sv/dnscrypt-proxy /var/service/
```

По умолчанию он слушает `127.0.0.1:53`. Дальше надо направить систему на него, то есть в `/etc/resolv.conf` оставить только:

```
nameserver 127.0.0.1
```

Чтобы этот файл не перезаписывался:
- **dhcpcd**: добавь `nohook resolv.conf` в `/etc/dhcpcd.conf`;
- **NetworkManager**: создай `/etc/NetworkManager/conf.d/dns.conf` с содержимым `[main]` / `dns=none`.

Проверка: `getent hosts www.youtube.com` должен вернуть адрес из сетей Google, например `142.250.x.x`. Затем снова «Проверить DNS» в приложении.

## Трей

Закрытие окна сворачивает приложение в трей. Иконка двухцветная: левая половина отвечает за сайты, правая за Telegram. На niri трей показывает твой бар (waybar `tray`, Quickshell `SystemTray`). Если трея нет, закрытие окна просто выходит из приложения.

## Настройки

`~/.config/byedpi-tg/config.json`. Здесь всё, что есть в окне, плюс:
- `browser_cmd` — своя команда для кнопки «Браузер», `{port}` подставляется. Пусто — браузер ищется автоматически. Пример: `"brave-browser --proxy-server=socks5://127.0.0.1:{port}"`.
- `discord_cmd` — то же для кнопки «Discord».
- `probe_timeout` — таймаут на адрес при проверке (8 с).
- `probe_fingerprint` — отпечаток TLS в проверках: `firefox` или `chrome`.
- `ipv4_only` — флаг `-X`, по умолчанию включён.
- `custom_targets` — свои адреса: `[{"service": "discord", "url": "https://…", "min_bytes": 0}]`.
- `extra_proxy_domains` — дополнительные домены для PAC.
